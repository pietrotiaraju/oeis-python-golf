# Programs read and approved: the first 12 hex digits of the SHA-256 of the program, then why
# it computes the sequence for every n. This file changes only through pull requests.
9397c20bcba3 Finite sequences (keywords fini, full): a(n) is m written in base 10-n for n = 0..9 and read as a decimal number, base 1 being unary (m ones) as in the OEIS data, with m = 9, 8, 7, 6, 5, 4 for A001731..A001736. There is nothing to compute beyond these ten values, so each program stores them (as decimal text, as a range plus '1'*m, or one character per term whose code point is the term, read back with ord) and stops after printing them. Each page derives every term from the base-b expansion m = sum of d_i*b^i (and m ones for base 1), so the stored values follow from the definition, not from the b-file; the program is correct for every n because n only runs over 0..9.
