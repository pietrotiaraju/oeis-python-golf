# Programs read and approved: the first 12 hex digits of the SHA-256 of the program, then why
# it computes the sequence for every n. This file changes only through pull requests.
bf2e0ec15188 a(n) = max number of MOLS of order n. For prime powers (detected exactly: lcm(1..n) > lcm(1..n-1)) the program prints n-1, by two theorems stated on the page: at most n-1 MOLS for every n (normalize first rows; the cell below the first holds distinct nonzero symbols) and n-1 MOLS from GF(q) (Moore 1896, Bose 1938). For other n it searches k = 2, 3, ... (stopping at the first k with no k MOLS, or at n-1): a square is a partition of the cells into n permutation matrices; orthogonality = every permutation of one square meets every permutation of another in exactly one cell, which the search enforces with agreement counts (1 against finished squares, 0 inside the square being built). Normalization only uses symmetries that preserve orthogonality (relabel each square's symbols: first row in order; permute rows of all squares: first column of the first square in order). So the search is exhaustive; for n = 6 it re-proves Tarry (no pair) in about 20 s. The program then searches for 3 MOLS of order 10 (open), beyond the b-file.
