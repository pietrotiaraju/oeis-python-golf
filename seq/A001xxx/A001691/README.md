# A001691

> Number of two-element generating sets in the symmetric group S_n.
> — [OEIS A001691](https://oeis.org/A001691)

Offset 1: 0, 1, 9, 108, 3420, 114480, 7786800, 497266560, 42616445760, …

### Python 3 — 288 bytes

```python
from itertools import*
def C(*g):
 G=F={*g}
 while F:F={tuple(x[i]for i in h)for x in F for h in g}-G;G|=F
 return G
n=1
while 1:P={*permutations(range(n))};d={};print(sum(d.get(k:=sum(n**len({g[i]for g in C(a)})for i in a))or d.setdefault(k,sum(C(a,b)==P for b in P))for a in P)//2);n+=1
```

**How it works**

A brute-force count straight from the definition: a(n) is the number of
sets {a, b} of two distinct permutations of {0, …, n−1} that generate the
whole symmetric group.

- `C(*g)` is the subgroup generated by the permutations `g` (tuples):
  a breadth-first search that multiplies the newest elements `F` by every
  generator (`tuple(x[i]for i in h)` is x∘h) until nothing new appears.
  In a finite group the products of generators already form the
  generated group (each g has g^k = identity), so no inverses are needed.
- `P` is the set of all n! permutations, and ⟨a, b⟩ = S_n exactly when
  `C(a,b)==P`. The program counts the ordered pairs (a, b) that generate
  S_n and halves the count. For n ≥ 3 a single permutation generates a
  cyclic group, never S_n, so a = b never counts and every set {a, b} is
  counted twice. For n = 1 and n = 2 the count is 1 and 3 (the pairs with
  a = b that generate S_1 and S_2 are not sets), and `//2` turns them
  into the right 0 and 1.
- Speed: conjugating a and b by the same permutation preserves
  generation, so f(a) = #{b : ⟨a, b⟩ = S_n} depends only on the
  conjugacy class of a, that is on its cycle type. The program computes
  f once per class and remembers it in `d`, which makes a(6) 65 times
  cheaper. The key is Σ_i n^ℓ(i), where ℓ(i) is the size of the orbit of
  i under ⟨a⟩ (the length of i's cycle). It is a sum Σ c_ℓ·n^ℓ where c_ℓ
  is the number of points on cycles of length ℓ and Σ c_ℓ = n, and it
  determines the cycle type: if every c_ℓ < n these are the base-n
  digits of the key; otherwise a single c_ℓ = n and the key is n^(ℓ+1),
  whose digit sum 1 cannot be the digit sum n of the other keys.
- `d.get(k)or d.setdefault(k,…)` computes f only when the class has no
  nonzero value yet; a class with f = 0 (such as the identity) is simply
  recounted, which costs nothing much.

**Notes**

- Correct for every n by the definition alone (the cache only uses that
  conjugation preserves generation); only the speed limits it. a(1)–a(5)
  come out at once and a(6) after about 15 s here (7,920 closures); a(7)
  needs 75,600 closures of up to 5,040 elements, well over ten minutes.
  The bar is 6 terms in 60 s.
- The 6 terms fit in a table shorter than the program, so it needs a
  review.

### Python 3, 5 terms — 208 bytes

```python
from itertools import*
def C(*g):
 G=F={*g}
 while F:F={tuple(x[i]for i in h)for x in F for h in g}-G;G|=F
 return G
n=1
while 1:P={*permutations(range(n))};print(sum(C(a,b)==P for a in P for b in P)//2);n+=1
```

**How it works**

The same count without the class cache: it tries all n!² ordered pairs.
The closure `C` and the halving are as above. a(5) (14,400 pairs) comes
after about 5 s here; a(6) would need 518,400 closures of up to 720
elements, over half an hour, so the record stops at 5 terms. It is
correct for every n and keeps going.
